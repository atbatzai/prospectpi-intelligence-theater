# Story 1.3: WebSocket Real-Time Progress System

## Status
Done

## Story
**As a** ProspectPI Intelligence Theater frontend user  
**I want** real-time progress updates via WebSocket connections during dossier generation  
**so that** I can see live progress from all three agents in the Agent Progress Theater component

## Acceptance Criteria
1. WebSocket server at `ws://api.prospectpi.com/ws/research/{requestId}` for real-time agent progress updates
2. Agent progress messages broadcast to connected clients with structured AgentProgress interface
3. Connection management with authentication, heartbeat, and automatic reconnection handling
4. Integration with Three-Agent Orchestration System to receive live status updates
5. Progress message queuing and delivery guarantee for reliable client updates
6. Error state broadcasting with recovery instructions and user-friendly messages
7. Connection scaling to support multiple concurrent research requests
8. WebSocket connection cleanup and resource management
9. Integration with Lovable frontend Agent Progress Theater component

## Acceptance Criteria
1. WebSocket server endpoint matches Lovable frontend expectations: `ws://api.prospectpi.com/ws/research/{requestId}`
2. Real-time progress updates for all three agents (Intelligence Coordinator, Field Researcher, Detective)
3. Structured message format matching AgentProgress interface from Lovable documentation
4. Connection authentication and authorization using JWT tokens
5. Heartbeat/ping-pong mechanism for connection health monitoring
6. Automatic reconnection handling on client disconnect
7. Progress message persistence and replay for late-connecting clients
8. Integration with Three-Agent Orchestration System (Story 1.1) for live updates
9. Error broadcasting with detailed recovery instructions

### TypeScript Interfaces for WebSocket Communication
[Source: docs/stories/lovable-prompt.md#agent-progress-interface]

```typescript
// Agent Progress Interface (CORE MESSAGE)
interface AgentProgress {
  stage: 'planning' | 'researching' | 'analyzing' | 'synthesizing' | 'quality_check';
  agent: 'intelligence_coordinator' | 'field_researcher' | 'intelligence_detective';
  message: string;
  confidence: number;
  estimatedTimeRemaining: number;
  userCanInterrupt: boolean;
  dataSourcesActive: string[];
  insightsDiscovered: number;
}

// Complete WebSocket Message Format
interface WebSocketMessage {
  type: 'agent_progress' | 'connection_status' | 'error' | 'completion';
  requestId: string;
  timestamp: string;
  data: AgentProgress | ConnectionStatus | ErrorInfo | CompletionInfo;
}

interface ConnectionStatus {
  status: 'connected' | 'authenticated' | 'subscribed';
  message: string;
}

interface ErrorInfo {
  code: string;
  message: string;
  recoverable: boolean;
  recovery_instructions?: string;
}

interface CompletionInfo {
  status: 'complete' | 'failed';
  dossier_url?: string;
  summary: string;
}
```

### Authentication and Security
```typescript
// WebSocket Authentication Flow
1. Client connects with JWT token in query parameter or header
2. Server validates JWT and extracts user information
3. Server verifies user has access to specific requestId
4. Connection established and added to ConnectionManager
5. Client subscribed to progress updates for their requestId

// Connection URL with Authentication
ws://api.prospectpi.com/ws/research/{requestId}?token={jwt_token}

// Or via WebSocket headers
headers: {
  'Authorization': 'Bearer {jwt_token}'
}
```

### Message Persistence and Replay
```sql
-- WebSocket Messages Table for Replay
CREATE TABLE websocket_messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    request_id VARCHAR(50) NOT NULL,
    message_type VARCHAR(50) NOT NULL,
    agent VARCHAR(50),
    stage VARCHAR(50),
    message_content TEXT NOT NULL,
    confidence INTEGER,
    estimated_time_remaining INTEGER,
    data_sources_active JSON,
    insights_discovered INTEGER,
    created_at TIMESTAMP DEFAULT NOW(),
    delivered_at TIMESTAMP
);

-- WebSocket Connections Table
CREATE TABLE websocket_connections (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    connection_id VARCHAR(100) UNIQUE NOT NULL,
    user_id UUID NOT NULL REFERENCES users(id),
    request_id VARCHAR(50) NOT NULL,
    connected_at TIMESTAMP DEFAULT NOW(),
    last_ping TIMESTAMP DEFAULT NOW(),
    disconnected_at TIMESTAMP
);
```
